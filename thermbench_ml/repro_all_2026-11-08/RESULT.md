# Full tank table reproduced from the release: all 96 checkpoints (8 November 2026)

**Scope:** extends `repro_2026-11-07` (the 24 hybrid + canonical checkpoints) to every neural row of the
tank table: 2 architectures × 4 variants (plain, canonical, hybrid, hybrid + canonical) × 3 seeds × 4 splits.

**Method** (`repro_all.py`, log in `repro_all_log.txt`, rows in `repro_all.json`):
- Uses only the frozen manifest (md5 0e8b6d8d...), the frozen h5 data and the checkpoints in
  `results_merged/ckpt`.
- The input encoder is rebuilt from each split's training runs; the cached encoder json is not used.
- Each checkpoint is scored with the unchanged `train.Predictor` + `evaluate.evaluate` (stride 10), and every
  test run is compared with the score its training job stored (`results_merged/<split>.json`).

## Result

- **96 of 96 checkpoints reproduce their stored scores exactly:** 19,704 per-run field-RMSE scores
  (`rmse_theta`, the metric compared run by run), maximum difference 0.0.
- **Review (8 November):** milestone closed. The checkpoint correction below counts as a finding of the
  audit: it caught a release file that would have prevented reproduction.
- One checkpoint needed correcting first (below).

## The one correction: U-Net, ood_flow, seed 2

- **First pass:** this entry differed, at 9.616 % against the stored 9.445 %, with runs up to 6.1 pp apart.
- **Cause:** the file in `results_merged/ckpt` (md5 532c650e..., copied 7 November) was not the checkpoint of
  the job that produced the stored score.
  - That job ran on the lab (started 5 November 17:09; stored score from `results_workers/lab`).
  - The lab's own checkpoint (`~/thermbench_ml/results/ckpt`, md5 0dc3e872..., saved 18:10 during that
    job) is a different file.
  - The wrong file most likely comes from an earlier attempt at the same job on pc5, before pc5 failed and
    its jobs were moved (5 to 6 November).
- **Fix:**
  - the lab's checkpoint replaces it in `results_merged/ckpt`;
  - the wrong file is kept as `results_merged/ckpt_unet_s2_ood_flow.pt.WRONG_SOURCE_532c650e`;
  - rescored: 9.445 %, all 103 runs exact.
- **Impact:**
  - **No reported number changes.** Tables, statistics and the multinode comparison use the stored
    per-run scores, which were correct.
  - Only the released checkpoint for this one non-headline row was wrong. The release must ship the
    corrected file.
  - Lesson for the release: checkpoints are taken from the worker that produced the stored score, and
    checked by rescoring, as done here.

## What this establishes

Every neural row in the tank table can be regenerated by a third party from the released data and
checkpoints, to the last digit, on different hardware from training (laptop RTX 4060; training was on six
GPUs).
